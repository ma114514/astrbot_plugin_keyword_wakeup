# 指定群关键词唤醒

开发版 **v1.0.1**，插件名 `astrbot_plugin_keyword_wakeup`。验证基线为 AstrBot **4.28.2**，平台为 QQ／aiocqhttp（OneBot v11）。插件无额外运行依赖。

指定群消息包含任意关键词后，先由 LLM 根据自定义规则和最近收到的群消息判断。只有判断通过，才交给 AstrBot 默认 AI 正式回答。已有 @、前缀等唤醒方式沿用原流程，不额外判断。

## 安装与配置

从 [v1.0.1 Release](https://github.com/ma114514/astrbot_plugin_keyword_wakeup/releases/tag/v1.0.1) 下载 `astrbot_plugin_keyword_wakeup_v1.0.1.zip`，在 AstrBot WebUI 插件管理中上传该文件，打开插件设置，填写群列表、关键词和判断规则，保存并重载插件。也可将 ZIP 中的插件文件夹复制到 `data/plugins/` 后重载。

本版按开发版处理，不迁移旧配置，不提供旧版直接唤醒模式。请按本版配置重新核对设置。源码与版本安装包发布在 [GitHub 仓库](https://github.com/ma114514/astrbot_plugin_keyword_wakeup)，尚未提交到 AstrBot 插件市场。

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `group_ids` | `[]` | 实际群号字符串列表，每项一个；不用完整会话标识 |
| `keywords` | `[]` | 多个群共用的普通文本关键词，每项一个 |
| `judge_provider_id` | 空 | 从已有提供商中选择判断模型；留空使用当前会话模型 |
| `judge_prompt` | 保守判断示例 | 可完整修改什么情况下需要回答 |
| `context_messages` | `20` | 带入此前最近收到的群文本条数，允许 `0–100`；`0` 表示只看当前消息 |
| `judge_timeout` | `15` | 判断超时秒数，允许 `1–120` |

群号和关键词均为字符串，去除首尾空白、忽略空项并去重；任一列表为空时停用关键词唤醒。关键词区分大小写，不解析正则，例如 `Bot` 不匹配 `bot`，`.*` 只匹配字面字符。配置类型、范围或判断规则无效时记录警告，停用本插件的关键词唤醒。通过 WebUI 保存后重载生效。

默认判断规则可以直接修改，不需要变量占位符：

> 结合群聊上下文，判断当前消息是否在呼叫机器人、向机器人提问或请求帮助。只是提及名字、转述或群友互聊时不回答；无法确定时不回答。

例如群号填 `123456789`，关键词分别填 `小助手`、`机器人`。发出 `小助手，今天适合跑步吗？` 后，模型根据判断规则决定是否放行；并非命中关键词就一定回答。需要严格控制行为时，修改判断规则，再用真实群消息检查效果。

## 判断和正式回答

判断模型通过 `context.llm_generate()` 独立调用，不传工具和正式会话历史，也不将判断内容写入正式会话。输入 JSON 包含机器人 ID、命中的关键词、当前消息和此前的群消息；每条消息含接收时间、发送者 ID、名称和文本。

自定义规则放入系统提示词，插件追加输出要求；群消息放入独立的 JSON 输入，作为待分析数据。判断模型必须仅返回：

```json
{"should_reply": true}
```

或：

```json
{"should_reply": false}
```

只接受 JSON 对象中的布尔值 `should_reply`。解释文字、Markdown 代码块、字符串 `"true"`、数字 `1`、缺少字段等都不算有效判断。返回 `false`、格式错误、模型不可用或超时时，本插件不新增唤醒；失败记录警告，拒绝结果记录调试日志，不重试、不自动切换其他模型、不在群里发送错误提示。

判断通过后只设置当前事件的唤醒标记，由 AstrBot 使用当前会话的模型、人格和上下文正式回答。判断用的群历史不会额外注入正式回答；判断模型输出也不会作为群回复发送。同一消息命中多个词只判断一次，后续消息需要重新命中，不进入持续唤醒状态。通过时通常有一次判断请求和一次正式回答请求，两者均可能产生模型调用费用。

已经被核心通过 @、前缀等方式唤醒的消息不调用判断模型。非目标群、私聊、机器人自身消息和未命中消息不调用判断模型。本插件不清除已有唤醒标记，不停止其他插件处理，也不会解除已有的 AI 禁止标记。

正式回复仍需满足核心白名单、会话开关、AI 开关、限流和其他插件规则。默认 AI 必须已启用，并将 **AI 额外唤醒前缀 `provider_settings.wake_prefix` 留空**，才能只靠关键词放行；机器人的普通前缀 `wake_prefix` 无需删除。相关接入依据为 [4.28.2 模型接口](https://github.com/AstrBotDevs/AstrBot/blob/v4.28.2/astrbot/core/star/context.py#L158)与[默认 AI 入口](https://github.com/AstrBotDevs/AstrBot/blob/v4.28.2/astrbot/core/pipeline/process_stage/stage.py)。

## 群消息缓存

只缓存插件实际收到的指定群中其他成员的非空文本，按平台实例、机器人账号和实际群号隔离。同群不同成员共享判断上下文，不受隔离会话 ID 影响。缓存不补拉历史、不收录机器人自身消息，也不通过发送钩子推断机器人已经发出的文本。

每条历史文本最多保留 2000 个字符；当前待判断消息单独传入，保留全文，不会在本次历史中重复出现。未命中消息以及原有 @、前缀消息也可作为后续判断的历史。缓存只留内存，重启、重载或停用后清空；不会自动读取正式 AI 对话记录。

历史快照在异步判断前固定，判断期间收到的后续消息不会混入本次输入。多条消息可以并发判断，正式回答顺序仍受模型响应速度和 AstrBot 会话锁影响，不保证按消息到达顺序回复。

## 验证

在源码插件目录运行离线测试：

```bash
python -m unittest discover -s tests -v
```

从源码验证时，先在插件源码目录运行以下命令生成安装包，再运行上述测试：

```bash
python build_package.py
```

测试包含模型调用替身，不连接 QQ、不请求真实模型。覆盖判断通过和拒绝、错误输出、模型异常和超时，以及缓存隔离、并发快照、配置校验和安装包源码一致性。安装包检查包含解压后加载插件并执行判断；这不等于在真实 AstrBot WebUI 中完成安装验收。

真实群聊验收需在满足正式回复前提后执行：

- 设置测试规则“只有问天气才回答”，发送命中关键词的天气问题和其他问题，检查是否分别放行和保持安静。
- 在同一消息中放入多个关键词，确认只正式回复一次；发送没有关键词的后续消息，确认不由本插件继续唤醒。
- 分别测试关键词大小写、非指定群、私聊和自身消息；原有 @、前缀行为应保持不变。
- 连续发送有话题关系的群消息，再发出含关键词的提问，检查模型能否利用最近上下文；修改历史条数并重载后再次测试。
- 分别选择独立判断模型和留空，检查提供商调用；模拟判断模型不可用，确认日志有失败记录且群里不新增回复。
- 使用两个群或两个适配器测试，确认判断上下文不串群；清空群列表或关键词列表，重载后确认关键词不再新增唤醒。

本版提供源码与 ZIP 安装包，未部署到 NAS、未提交到插件市场，也未进行真实 QQ 群聊或真实模型验收。
